# 🌐 Настройка онлайн-версии с Supabase

## ✅ Что уже сделано

1. **Установлен клиент Supabase** - приложение готово к работе с облачной базой данных
2. **Созданы хуки для работы с Supabase**:
   - `useEntries` - загрузка/сохранение ДЗ, ГДЗ, СРС
   - `scheduleStore` - работа с расписанием
   - `useCustomSubjects` - управление предметами
3. **Создан SQL скрипт** для создания таблиц в Supabase
4. **Двойная синхронизация**: данные сохраняются и в Supabase, и локально (IndexedDB)

## 📋 Шаги для запуска онлайн

### Шаг 1: Создание таблиц в Supabase

1. Откройте [Supabase Dashboard](https://supabase.com/dashboard/project/pcwqetnwnfczjsodzopb)
2. Перейдите в **SQL Editor** (в левом меню)
3. Нажмите **New Query**
4. Скопируйте весь код из файла `supabase-setup.sql`
5. Нажмите **Run** (или Ctrl+Enter)

После выполнения должны создаться 3 таблицы: `entries`, `schedule`, `subjects`

### Шаг 2: Проверка подключения

1. Запустите приложение локально: `npm run dev`
2. Откройте http://localhost:5173
3. Добавьте любое ДЗ или измените расписание
4. Проверьте в Supabase Dashboard -> Table Editor, что данные появились

### Шаг 3: Деплой на Vercel (бесплатно)

**Вариант A - через GitHub (рекомендуется):**
1. Создайте репозиторий на GitHub
2. Загрузите код проекта
3. Зарегистрируйтесь на [Vercel](https://vercel.com)
4. Подключите GitHub репозиторий
5. Vercel автоматически задеплоит приложение

**Вариант B - через CLI:**
```bash
npm install -g vercel
vercel --prod
```

### Шаг 4: Проверка онлайн-версии

После деплоя:
1. Откройте URL вашего приложения
2. Войдите с разных устройств/браузеров
3. Изменения должны синхронизироваться между всеми пользователями

## 🔧 Как работает синхронизация

```
Пользователь 1 → Изменяет данные → Supabase → Все пользователи видят изменения
Пользователь 2 → Изменяет данные → Supabase → Все пользователи видят изменения
```

- Данные загружаются из Supabase при запуске
- Изменения сохраняются в Supabase автоматически
- Локальный кэш (IndexedDB) работает как fallback при отсутствии интернета
- При восстановлении соединения данные синхронизируются

## 📊 Структура базы данных

### Таблица `entries` (ДЗ, ГДЗ, СРС)
- `id` - уникальный идентификатор
- `date` - дата создания
- `subject` - предмет
- `type` - тип (dz/gdz/srs)
- `content` - содержание
- `deadline` - дедлайн (для СРС)
- `attachments` - вложения (JSON)
- `links` - внешние ссылки (массив)

### Таблица `schedule` (Расписание)
- `id` - уникальный идентификатор
- `day_of_week` - день недели (1-6)
- `period` - номер пары (1-8)
- `subject` - предмет
- `week_type` - числитель/знаменатель

### Таблица `subjects` (Предметы)
- `id` - уникальный идентификатор
- `name` - название
- `emoji` - эмодзи
- `color` - цвет
